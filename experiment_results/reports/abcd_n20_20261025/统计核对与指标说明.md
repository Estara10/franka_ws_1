# ABCD n=20 批次统计核对与指标说明

## 样本与分组

- `formal_attempts.csv` 含 **80 行正式尝试**，A/B/C/D 各 20 行；80 个 `sample` 唯一，无重复编号。历史每组 3 次不在表内。
- 正式起点为首次预抓取 MoveGroup 执行请求被接受。正式结果按完整任务状态计算：A 20/20、B 20/20、C 19/20、D 20/20。完成率分母均为 20。
- C04 使用原始 `FAILED` 记录。其后补运行标记为 `post_batch_excluded_completed`，只留在 `attempts.csv` 和 `raw_run_index.csv` 的原始索引中；未进入80行主表、组统计或图表。
- 另有26条动作前启动/规划异常，保存在 `startup_failures.csv`，不进入正式分母；原始目录索引共107项（80正式、26启动异常、1后补未计入运行）。

## 口径核对

| 指标 | 统计样本 | 定义与核对结果 |
|---|---:|---|
| 完整任务 | 各组 n=20 | 从首次预抓取目标被接受起，抓取、抬升、运输、下降、释放和撤退均完成才记为 DONE。 |
| 释放平面位置误差 | A20、B20、C19、D20 | 释放读回杆中心相对目标中心的 XY 欧氏距离，mm；只用实际产生释放测量的完成任务，C04缺失值为空，不补零。 |
| 释放偏航误差 | A20、B20、C19、D20 | 杆偏航与目标偏航的绝对环绕角差，°；不代表完整三维姿态误差。 |
| 释放等待 | 各组 n=20 | 80份正式任务日志均有 `ABCD_RELEASE_MEASUREMENT` 标记，均按2.0 s仿真时间等待；实测范围2.000–2.062 s。组均值/标准差/中位数已纳入 `group_summary.csv`。 |
| 运输计划时长 | 各组 n=20 | 各次运输计划记录的时长，s。A/B内部及C/D内部可描述比较；因执行路径/控制实现不同，不把A/B与C/D计划时间解释为同一执行时间。 |
| 实际运输阶段时间 | 各组 n=20 | A/B为JTC MoveGroup action wall-clock；C/D为MMC参考播放仿真时间。两种时钟和事件边界不同，不能跨控制方式直接比较。C/D均有约2.24 s与3.02 s两个时长簇。 |
| 优化求解耗时 | B20、D20 | 每次时间剖面优化的计算耗时，s；A/C不适用。 |
| 连续 jerk RMS、峰值变化 | B20、D20 | 每次候选相对该次自身基础参考计算：`100×(候选值/基础值−1)`。优化前后保持同一条连续关节路径和总时长，候选均被接受并执行（B、D各20/20）；基础/候选导出间隔相同为5 ms，候选导出相对连续曲线的最大偏差不超过1.58×10⁻¹³ rad。指标是**连续时间参考曲线**的 jerk，不是机械臂实测 jerk。 |
| 抓取参考残差、杆运动范围及姿态代理 | 各组 n=20 | 来自承载阶段 `contact_probe.csv`；C04在失败前已完成承载轨迹至下降/释放验证阶段，因此保留其承载记录。残差是相对抓取参考的最大偏差，杆高度/X/Y为承载窗口内变化范围；左手 yaw 是姿态代理，数据中没有杆四元数时间序列。 |

## 优化比较口径核对

B、D各20次均保存同次基础和候选参考。优化器在同一个 `ContinuousPath` 与固定总时长上改变时间映射，不改空间路径；逐次记录中的候选均为 `selected=1`、`transport_ok=1`，且候选时长与自身基础时长完全一致。基础与候选采用相同5 ms导出间隔及一致的插值/连续曲线评价流程。导出 CSV 点数不同源于候选按5 ms重新采样，不代表空间路径改变；直接逐行比较两份不同密度导出文件不适合作为路径一致性检验。连续 jerk 的比较使用优化器保存的同一路径连续曲线基线/候选指标。

逐次百分比先按每次运行计算，再对20个百分比作描述统计；不是用两组均值相除。样本标准差使用 `n−1` 分母。正文组间差值为独立组均值差；本批虽按轮随机化运行顺序，但分析不把相同轮号当作真实配对样本，不作显著性或等价性推断，也不加入置信区间。

## C04直接原因及版本边界

C04到达下降后支撑确认，执行开爪并完成2.046 s仿真等待；随后在 `E_CONTACT_RELEASE_TRUTH_OR_FEEDBACK` 检查处退出。代码将 MuJoCo 杆真值读取与接触反馈有效性/新鲜度合并在同一失败分支，现存日志不能判定是哪一个子条件未通过。诊断快照显示双爪已张开、保持力为0且无接触，但任务没有写出 `CONTACT_PROBE_RELEASED` 成功标记，也没有发出撤退请求。可确认的是释放后的软件验证未通过、完整流程未完成；不能据此确认铝杆发生物理掉落或碰撞，也不能把根因定为随机因素。按预先采用的完成判据，C04保留为未完成正式尝试。

冻结配置记载批次准备时工作区 HEAD 为 `6bc974d3dd638f1dbc5ee82815eaa8883fff4bd1`，各正式任务使用同一已安装任务包及同一运动/控制配置。批次中 `scripts/a1_run_scene.sh` 仅修正启动器在runner退出后仍等待truth的流程；它影响启动失败传播，不改运动、控制、参数或结果判定。没有发现运动算法/阻抗参数版本分界，不需把正式样本拆批。
