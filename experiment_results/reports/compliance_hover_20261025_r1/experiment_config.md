# 柔顺控制补充实验配置（冻结）

批次：`compliance_hover_20261025_r1`。本批与80次ABCD、2026-10-20悬空专项及其他历史数据完全分开；历史目录和记录不改写。场景固定为杆初始 `(0.50, 0.00, +10°)`，真实无 weld 接触；沿用 2026-10-20 已完成的抓取位置、10 N/指夹持、杆/指垫接触与摩擦模型、0.64 kg 杆质量、50 mm JTC 抬升和 hover/MMC 入口。前置预抓取与抓取闭合由既有流程执行。观测使用双臂独立笛卡尔阻抗、共同静止位姿参考、零末端速度；机器人本体补偿开启状态按既有独立阻抗路径保持一致。控制器保持既有互斥：抬升/下降由 JTC，悬空窗口由 MMC，结束后正常回切 JTC、下降、释放；失败按现有收尾并保留运行。

阻抗坐标为各 `mj_{left,right}_link0`，模型中其方向与 world 对齐。两臂阻尼比均为 0.8，旋转刚度 `(20,20,20) N·m/rad`，零空间刚度 10；平移 Y/Z 均为 400 N/m。K400 条件 X=400 N/m；K200 条件 X=200 N/m。阻尼由现有控制器按 `D=2ζ√(ΛK)` 方法在线计算。本轮不改夹持力、质量、摩擦、接触、保护条件或其他控制参数。

载荷前馈为关闭/开启的唯一组间因素（实验一）：杆质量 0.64 kg，按两臂均分，每臂目标 `0.64×9.81/2 = 3.1392 N`，从首次被 MMC 确认接受的参考起按仿真时间线性渐增 0.5 s；F0 窗口全程发布 0 N。两组 K 均为 400 N/m且不施外力，观测从首条有效 MMC 参考确认开始计时，持续 3.5 s。

方向性刚度实验四组均启用相同载荷前馈。K400-N、K200-N 不施外力；K400-F、K200-F 复用现有物理线程入口，在杆质心施加 world `+X` 2 N，总脉冲 1.0 s；请求在首次有效 MMC 参考确认后启动，物理线程记录的 `pulse_start` 是实际对齐零点，`pulse_end` 是实际清零时刻。无外力组使用相同的窗口时序，按实际施力组事件时刻作虚拟脉冲起止点。观测窗口均为 5.0 s。

样本及次序见同目录 `schedule.csv`，实验一10个区组、每区组F0/F1各一次；实验二10个区组、每区组四条件各一次。每个样本独立重新启动场景和仿真，不在一次抓取中切换条件。首次预抓取运动请求被接受即计为正式尝试。动作前可确认的基础设施异常单列，不算正式样本；原因明确且不是同类异常已连续3次时，才按冻结顺序恢复。正式动作一经开始，中止和失败均保留、不替换。若同一专项在进入有效观测前连续两次由同一原因阻断，暂停该专项；连续3次同类启动异常也暂停相关批次。除上述有限规则外不增加扫描或运行。有效样本按各指标实际曲线覆盖统计，不补零；失败曲线保留并注明缺失阶段。

主要指标：实验一为相对观测入口、3.5 s末杆 world-Z 位移（下沉为负）；辅助为0.5–3.5 s杆位移变化、双手 world-Z位移、杆减双手相对位置变化和杆姿态变化。实验二主要指标为以实际 `pulse_start` 对齐的杆及双手 world-X原始位移曲线；报告脉冲结束、撤力后1 s和接近3 s可用时刻。响应估计为同刚度下施力组与无外力组的组均值差；交互差为K200响应减K400响应，属独立样本组均值差，不把区组自动当成同物理起点配对。并报告X/Y/Z、杆竖向下沉、姿态、任务完成和杆-手相对运动。仅用所有相关运行共同覆盖的时间区间，不外推尾段；精确撤力后3 s不可用时，报告最接近且实际覆盖的时刻。

组描述统计报告逐次值、均值、样本标准差、范围及有效n。组间均值差给出Welch独立样本95% t区间；方向性差中差用四组独立方差估计其标准误和Satterthwaite自由度。区组仅组织次序，除非后续数据证明相同物理起点，不使用配对检验。区间用于展示有限样本不确定性，不宣称显著性或总体可靠率。曲线展示全部合格运行、组均值及离散范围，不筛选“代表性最好”运行。

冻结后不因观测结果调整配置、分析口径或运行次数。此批不启用 `CONTACT_ABCD_MATCHED_WAIT_SEC`，不执行8秒承载匹配等待，不重跑ABCD，不研究路径/赋时/运输优化、协同wrench、自适应控制或内力控制。

## 冻结前核对

- 运行入口：`bash experiment_results/reports/compliance_hover_20261025_r1/run_batch.sh`；内部逐次调用 `bash scripts/run_contact_probe_local.sh --headless`。每次启动一个 MoveIt launch（其自身包含且仅包含一个 MuJoCo），域ID与 `ROS_HOME` 独立。原始数据写入 `experiment_results/a1_runs/<run_id>/`，调度日志写入本目录。脚本不自动重试；正式动作前异常保留后暂停，诊断后人工恢复顺序。
- 时序改动：`dual_impedance_no_load_bridge.cpp` 的悬空窗口/前馈斜坡以首条MMC参考确认时间为起点；外力请求在确认后立即发布。物理线程的实际 `armed/pulse_start/pulse_end` 仍作为外力时间依据，实际脉冲可能比请求的首参考后1 s晚一个DDS/物理周期。
- 定向构建：`rtk colcon build --base-paths src/multipanda_ros2 --packages-up-to dual_arm_carry_task --parallel-workers 2 --cmake-args -DMUJOCO_DIR=/home/lidio/Libraries/mujoco`，4包完成。
- 聚焦用例：`rtk ctest --test-dir build/dual_arm_carry_task -R 'test_payload_feedforward|test_bridge_process|test_mmc_activation_handshake' --output-on-failure`，3/3通过。
- 期间误运行的 `colcon test` 触发了包级全套检查：历史 copyright/cpplint/uncrustify/xmllint 项失败。直接筛选的3个相关CTest均通过；不修理或引用无关lint失败作为本实验阻断。
- 冻结的分析程序为 `analyze_batch.py`；已经通过 Python AST 语法解析。运行入口已通过 `bash -n`。F0只有双臂前馈 trace 全窗为零且MMC窗口有效时才计入前馈指标；其他各组按窗口、实发/虚拟脉冲事件及每项具体测量分别计有效n。
- 首次非正式启动因runner域号超出DDS范围（241）及默认沙箱禁止DDS接口/socket而在动作前结束，记为基础设施异常 `E_SIM_COMPONENT_DIED_AT_STARTUP`，运行目录保留。域号仅用于通信隔离，与实验因素/物理条件无关，已在启动前改成100–219范围；后续申请的本地socket权限只用于ROS 2仿真通信。该异常不计入60次正式尝试。

## 运行后执行记录（冻结条件未改变）

- 冻结表60个样本均进入正式计数：F0/F1各10次；K400-N/K400-F/K200-N/K200-F各10次。另有1次计划外 K200-F 初始化在恢复过程中被重复启动，完成后按执行偏差保留为 `K200-F_06_EXTRA`，不计入主分析。故实际有61次正式动作请求；主要统计仍严格按冻结表60个样本，每样本只取其第一次进入正式计数的运行。
- 7次动作前异常均留在 `attempts.csv`：域号/通信启动1次、MMC启动预检1次、P2B预抓取规划拒绝3次、MMC启动预检再1次和P2B拒绝再1次。原因明确后按有限规则恢复，未连续3次同类启动异常。正式失败2次均保留：K200-N_04预抓取动作接受后接触抬升起点位移超出既有限制，未获得窗口；K200-N_05取得完整窗口并测量，之后下降阶段报接触滑移/掉落，任务未完成。前者缺连续指标，后者指标仍有效。没有补跑正式失败。
- 运行过程中发现任务日志落盘晚于部分启动器状态检查。一次恢复判断把仍在运行的 K200-F_06_a1 暂视为未正式执行，之后额外启动 `K200-F_06_a2`；最终根据完整原始日志确认前者已完成，因此将后者标为计划外并排除。K400-N_06 的暂时中断记录也根据完整任务日志更正为同一运行正常完成。`attempts.csv` 保留逐次最终台账，原始日志均保留。
- F0 的20臂×10次 trace 全窗杆前馈实发均为0 N。F1 每次双臂目标均达到3.1392 N；从首个非零记录到达到目标99%的观测间隔0.516–0.522 s（均值0.519 s），与配置的0.5 s渐增相符到采样分辨率。
- 20次有力方向性运行的实际 `pulse_start` 均为首个有效MMC参考后1.000–1.002 s；实际持续1.000–1.002 s，事件记录为world +X总力2 N并在 `pulse_end` 清零。定向运行均使用冻结的5.0 s窗口；分析只取参考后0–5.0 s内记录。共同可用撤力后时点为2.891 s，未外推到准确3 s。
- 观测后批次驱动只调整了单次正式缺窗口后的停止判断：遵循冻结规则，只有下一次连续正式运行仍以相同原因在窗口前被阻断才暂停；前置异常仍停下人工检查。另移除了对 `rtk` 的冗余包装调用，不改变运行入口或条件。分析脚本只修正数据时间截断、逐次端点索引、单位换算和计划样本筛选；没有按结果改条件、运行次数或既定统计方案。结果按计划样本映射排除唯一计划外运行。
