最终状态恢复为：

```text

sim_multi_mode_controller inactive
```

watchdog 运行设置 `stop_reference_after_seconds=1.5` 后确认：

```text
MMC_SWITCH ... ok=1
MMC_FIRST_REFERENCE_SENT direct activation accepted
reference publishing stopped
MMC_HEALTH_LATCH reason=controller fault latched: reference_watchdog
```

watchdog 测试返回非零码是预期结果，因为它主动停止参考发布并锁存故障。watchdog 的作用是：当 bridge 或通信中断、超过约 0.5 s 没有新的有效末端参考时，MMC 保留最后有效目标并锁存故障，防止上层失联被误判为正常运行。

## 二、今天修复的代码问题

### 1. MMC 状态时间校验

原 bridge 用不同发布链路的 `/joint_states` 或 bridge `/clock` 时间去否定 `get_robot_states` 刚返回的状态，造成 `stale_state_sample_left`。当前校验以同一服务响应的 `FrankaState.time` 作为本次状态对，保留墙钟时间戳新鲜度检查和双臂状态合法性检查。

### 2. `o_t_ee` 矩阵解析

独立 controller 服务与任务节点服务存在矩阵数组布局差异。当前 `mmc_state_validation.hpp` 支持检查列主序和行主序，并使用有效的齐次变换、旋转矩阵和四元数检查结果。

### 3. RobotData 状态快照

`RobotData::state()` 原来返回解锁后的内部引用，控制循环更新状态时，`SwitchEngine` 可能读取到被并发改写的 `O_T_EE`。现在返回加锁后的 `franka::RobotState` 值快照，避免服务响应中的矩阵撕裂。

### 4. 独立 bridge 的激活顺序

独立 bridge 直接使用 `/mj_left_and_mj_right/get_robot_states` 时，MMC 尚未激活，SwitchEngine 的 RobotData 状态可能尚未准备好。当前对该独立服务采用：

```text
健康检查
→ 严格 JTC→MMC 切换
→ 确认 MMC active、JTC inactive
→ 读取状态快照
→ 发布首个参考
→ HOLD/watchdog
```

任务节点自己的 `/dual_arm_carry_task/current_robot_states` 仍使用 MoveIt FK 服务路径。

## 六、数据和结论口径

- 当前 MuJoCo 铝杆质量约 `0.64 kg`，不与目标质量 `0.5 kg` 混用。
- `JTC/MMC` 悬空结果是杆世界位移和抓取参考残差，不等同于局部指垫滑移。
- 反馈、杆真值和左右手状态异步采样；力尖峰不能直接解释为稳定承载力。
- S2 几何投影约 `1.47%`、连续时间 jerk 约 `3.15%` 是有限离线样本结果，没有执行收益证据。
- MMC 杆重前馈降低了既有悬空保持中的整体竖向下沉，但不代表全面抗滑或完整运输优势。
- 方向性脉冲实验每组 n=3，只能报告描述性让步和残余，不能报告统计显著性或抗扰优势。
