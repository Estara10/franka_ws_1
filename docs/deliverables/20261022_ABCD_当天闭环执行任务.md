每次使用新 run id；复用 `scripts/run_contact_probe_local.sh --headless`，
通过 `CONTACT_PROBE_ABCD_GROUP` 选择组别，显式传入本任务固定起终点和时间倍率。

`CONTACT_PROBE_HOLD_DIAGNOSTIC_ONLY=0`，关闭杆外力脉冲和旧的 `CONTACT_TRANSPORT_PAIRING` 开关，
避免同时走两条优化路径。核对环境继承即可，不新增一套运行前检查系统。

每次只启动一个 MuJoCo 实例；JTC/MMC 不得同时 active。
脚本回收本次仿真后直接继续下一组，不逐次征求确认。

## 5. 必须把比较指标留全，计算放到运行结束后

复用现有 `writeTrajectoryCsv()`，不要再出现只保存候选、不保存其同一路径基础轨迹的情况。
每次保留运输基础 q/t/v/a；B/D 还保留优化候选 q/t/v/a；实际下发含连接时另存最终消息，
连接时间单列。保存一次简短说明即可，不增加哈希或审计系统。

B/D 现有 `TimeProfileCandidateInfo` 已包含以下值，直接保存为简短结果行：
同一路径基础/候选的连续 jerk RMS 与峰值、导出 jerk RMS 与峰值、导出位置偏差、时长和求解耗时。
不要在悬空时再做一轮昂贵的重复评估。基础和候选用同一关节顺序、同一统计公式和采样方法。
它们当前采用同一基准总时长；不同运行自身基础时长可能不同，应分别报告。

结束后用一个离线脚本生成 CSV 和图：

1. **流程结果：** 每次完成到哪一阶段、是否释放和撤退、失败原因、阶段/整程耗时。
2. **轨迹优化：** B/D 每次相对自身基础路径的连续 jerk 变化；导出后指标及导出偏差另列。
   不把不同几何路径的绝对 jerk 差，或粗采样插值偏离路径带来的变化，直接算成优化收益。
3. **落放结果：** 释放后物理杆真值到目标的 XY 平面位置误差、绝对 yaw 误差；
   Z/杆底面支撑误差单列，目标高度由预先固定的支撑面和杆尺寸确定。
   使用相同释放后等待时刻，不把某组释放前数据与另一组释放后数据比较。
4. **控制表现：** 运输/下降期间的现有跟踪误差和抓取参考残差；残差不称为直接指垫滑移。
   已有力曲线可作辅助图，异常尖峰保留并说明，不把可疑峰值作为控制优越性的主要依据。

主图只需三张：四组完成情况与落放误差、同路径优化前后 jerk/耗时、完整搬运期间杆的空间轨迹。
每次运行都显示，附均值和范围；每组仅三次，不做统计显著性承诺。
优先比较 A/B、C/D 的轨迹变化，以及 A/C、B/D 的控制组合差异。
不要求每项都优于基线；如无收益，说明功能已实现但该场景效果有限。
既有载荷前馈减少下沉、方向性低刚度增加让步的结果可以继续用于结题，不需要重新跑一遍。
