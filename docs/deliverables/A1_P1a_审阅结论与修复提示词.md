## 原审阅分析（事实保留，旧处理要求按上方现行范围调整）

### R1：高，取消与超时尚未约束写入/成功

`a1_sampling.cpp:651` 开始写入，直到 `:701` 才检查 abort。预先取消或等待服务期间取消
仍可能产生写入。`:776` 接受 STABLE，`:799` 才检查 deadline，因此阻塞读回后超过预算
也可能成功。写前及每次阻塞操作返回后检查取消和时限；取消/超时优先于成功。
写前取消应 0 次写，写后取消仍保留“可能已应用”记录，绝不再写。

ROS 调用等待同样要有取消与剩余预算边界，清理本地超时 pending request；明确这不取消
服务端操作。所有读取保存请求/响应的 steady/ROS 时间区间，不能只把请求前时刻当采样时刻。

### R2：高，健康观测失败被忽略

`a1_sampling.cpp:756–765` 在 getSimInfo 失败时继续沿用旧状态，也未检查新的 model_valid。
sim_paused 初值还忽略 sim_info_before.paused。成功前必须有一次有效的最终健康确认，
核对 paused、model_valid、model_path/load_count 与起始合同；健康失败不得忽略。
前置 paused/无效/不符模型须 0 次写。模型路径与基线状态现在主要打印，需实际核对。

### R3：高，固定 ROS domain 不等于独占新实例

脚本默认 domain 77，未在启动前检查已有服务提供者，`:277` 只看服务名存在即继续。
同 domain 的另一仿真实例可能接收写请求；已有死进程也只在执行后查看日志。
在写入前确认本轮独占与必要组件健康。启动前发现已有相关节点/服务须拒绝，不清理他人；
并发本脚本还需互斥/明确的隔离机制。通过“相同模型路径”不能证明实例归属。
发现启动阶段组件死亡应在写前停止；所有 discovery CLI 都加墙钟超时，当前 service list
未受 READY_TIMEOUT 单次调用约束。

### R4：高，运行记录可覆盖或落盘失败却返回成功

脚本 `:163–167` 只拒绝已有 manifest，仍复用没有 manifest 的失败目录并截断日志；
节点只在最后 writeManifest 中检查旧文件，可能先写仿真、先覆盖 CSV，才拒绝清单。
`:978`、`:1018` 的返回值被忽略，落盘失败仍可能 exit 0。run_id 未限制路径分隔与 `..`。

要求运行目录在任何副作用前独占保留，重用任何已开始的 run 都拒绝；直接调用节点也要
满足，不仅依赖脚本。脚本启动失败、等待超时、参数异常与信号退出都生成可机读记录，
节点和脚本明确谁负责哪份文件。清单/必需原始数据落盘失败为非零退出，区分“场景动作
成功”与“证据持久化失败”；保留临时文件，不能覆盖旧结果。

脚本只有 EXIT trap，需验证 SIGINT/SIGTERM 能回收自有 runner、tee、timeout 与仿真
子树；不能只测试直接向节点发信号。无需改外部进程，也无需扩大清理范围。

### R5：中，完整配置尚未验证或记录

canonicalString/checksum 仅包含 SamplingConfig 的 18 项，不包含稳定阈值、超时、轮询、
服务名/对象名、max_write_attempts_per_run 等实际配置。修改这些值清单校验和不变。
新稳定/策略参数目前缺少 finite、正数、上下界校验；max_write_attempts_per_run 声明却
不读取。CLI stoll→int32 强制转换可溢出，stod/stoll 也未检查尾随字符或重复标志。

在服务交互前严格验证全部有效配置，保留采样子配置 checksum 并增加完整运行配置及
来源快照/hash。单写策略固定为 1，禁用健康检查等配置不得静默接受。当前 footprint/
高度仅适用于平躺纯 yaw，P1a 应拒绝非零 roll/pitch，不扩大倾斜物体支持。四元数及
实际读回姿态需验证非零范数与归一化合同，不能仅检查分量有限。

### R6：中，关闭审计在 cleanup 前结束

三个实际 sim_dual_moveit.log 最终均含进程死亡；脚本 `:322` 在 EXIT cleanup 前检查，
所以 shutdown 崩溃未进入分类，也没有相应 sim_stack_deaths.txt。这不否定场景已应用，
但不能据此报告整个生命周期干净退出。

将应用结果与 startup/runtime/shutdown 健康分别记录，cleanup 完成后再做最终审计。
已知关闭崩溃可以保留为独立警告/退出分类，无需本轮修 mujoco_ros/move_group。
对文档中的“全部失败均保留”、首次 n10 启动失败已记录等声明，核对实际文件；找不到
原始记录时明确未保存/无法验证，不根据后来的成功日志补造证据。

已知位姿表目前主要来自稳定后读回，避免把它解释为独立的即时写入精度测量。
A0 两次 DONE 加一次 ERROR 只能证明入口仍可运行、存在间歇故障；不能据此证明可靠性
未退化或将夹爪根因确定为 client 每次新建。全量 lint 结果的生成时间和检查范围也要
注明，既有问题与新增文件问题分别报告，不把旧结果当成本轮全面检查。
