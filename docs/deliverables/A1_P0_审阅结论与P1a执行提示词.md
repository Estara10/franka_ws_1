# A1 P0 审阅结论与 P1a 执行提示词

**效力说明：本文件是已执行 P0/P1a 任务的历史审阅与提示词，保留当时的分析依据。**
其全量配置哈希、记录字段、单独审查等要求不作为后续长期准则，不重复执行该提示词。
后续开发以 [项目指南](../PROJECT_GUIDE.md) 的当前定位、适度验证和问题分级为准；
当前 P1a 的范围取舍见 [P1a 审阅文件](A1_P1a_审阅结论与修复提示词.md) 顶部更新。

## 审阅结论

**结论：需修改；保留技术路线，允许先修正文档，再实施受限 P1a。**

规划器已只读核对 P0 文档及服务、物理循环、任务、夹爪、构建依赖相关源码。此次审阅
未构建、启动或运行实验，不把源码分析当作运行证据，也未修改生产代码。

认可的方向：复用 `/set_body_state` 与 `/get_body_state`；不直接写 MuJoCo 状态；保持
0.64 kg 基线；建立非交互入口；将真值与视觉分离；将完整搬运路径与样本初始有效性分开。
服务写位姿确实取得物理线程锁，但这只能证明该段写入与步进互斥，不能单独证明整个
启动、模型重载、服务超时和任务生命周期安全。

## 必须修正的发现

1. **高：真值时间戳缺失及启动时序冲突。**
   `src/mujoco_ros_pkgs/mujoco_ros/src/ros_two/ros_api.cpp:282` 和 `:292` 创建默认 Header，
   只填 frame，返回 stamp 为零。不能直接用它做新鲜度判断。P0 §4.7 的“一次发布 +
   stamp 晚于任务 INIT + 新进程发布”也无法同时保证先准备场景、后启动任务：先发会被
   判旧，writer 退出后 transient_local 不保证后来订阅者拿到历史。
   P1a 记录请求/响应的 steady-clock 和 ROS 仿真时间区间；不得伪造精确物理采样时刻。
   P1b 另行审阅带 run_id 的握手和生命周期契约；两个独立 latched 话题不能保证原子配对。

2. **高：稳定判据会接受暂停或持续漂移。**
   25 次轮询不等于 0.5 s 仿真进展；重复读暂停状态也会满足相邻增量。0.5 mm/20 ms
   还可能接受明显慢漂移。要求仿真时钟有效且持续前进、窗口有最小仿真时长、整个窗口
   的位置/角度变化受限、有效 twist 范数受限；服务与整体超时使用 steady-clock。
   暂停、回跳、模型重载不能输出成功。高度与倾角只是静止几何判据，不能证明真实接触。

3. **高：服务失败/超时后不能立刻重试写入。**
   ROS service 超时不取消服务端操作；旧写请求可能稍后生效。`SetBodyStateCB` 对 TF
   失败还可能先清零 twist 再返回 failure，响应失败不等于没有副作用。写请求超时或
   状态不明时停止本轮，标记不确定结果，不再写下一候选。先确认模型就绪、杆身份与
   基线状态；每轮优先使用执行器自行启动的新仿真实例，禁止对未知会话应用位姿。

4. **中：P1a 验收与修改范围矛盾。**
   P0 §10 不接任务、不改 PlanningScene，却要求三者一致。P1a 只验收“候选→仿真应用→
   稳定读回→清单”，状态应是 SCENE_READY_UNVALIDATED；不能填 accepted=true。
   任务输入及 PlanningScene 一致性留给 P1b，实际抓取留到 P2 检查与必要可靠性修复之后。
   P1b 不提前做 yaw 运动泛化或放置评价；它们分别属于共享目标构造/P2–P3 和 P3c。

5. **中：配置与依赖需要落实。**
   §4.2 的 `rod_target` 位于 `ros__parameters` 外，不可直接作为标准 ROS 参数加载；
   `sample_x_yaw_only` 与同时采样 y 的定义冲突。清理这些字段，先只保留 P1a 所需内容。
   C++ 服务客户端需要在 CMakeLists.txt 和 package.xml 声明 mujoco_ros_msgs；测试依赖
   也按实际用法声明。不得安装新依赖，缺失时报告。

6. **中：A0“天然不退化”只能表示默认入口未改。**
   同一仿真进程被改过位姿后，不启动 runner 不会自动恢复 XML 初态。A0 回归须在新实例
   中使用当前真实存在的参数；P0 §7.3 的 rod_pose_source:=static 尚未实现，本轮不用。
   手动启动与旧一键脚本的柔顺环境变量不同，记录实际配置，不能把差别归因于 A1。

7. **中：几何与模型表达结论应收敛。**
   world/base_link 数值对齐是当前模型的配置假设，不代表 TF 链已存在。抓取公式在平躺
   与 yaw 旋转假设下可保留为候选推导，末端实际 link/TCP 必须读运行配置后确认。
   MoveIt 单 link attach 是常规表达；缺口是右手相对物体约束及碰撞处理未明确，不能
   仅因物理双 weld 就断言 attach 错误。SRDF 对照检查应“收紧 ACM”，重新启用非必要
   禁碰对；“放宽 ACM”通常会允许更多碰撞，原表述需修正。

8. **中：验证项与断言需准确。**
   通过服务设置四元数并读回不能验证 XML euler 解析，V5 标为不属 P1a 服务往返试验。
   Ruckig 后复检要求不以航点位置是否变化为条件，时间参数化、插值仍可能影响约束。
   “不存在任何话题/接口”的结论限定到当前启动链与已检查组件；避免全仓绝对断言。
