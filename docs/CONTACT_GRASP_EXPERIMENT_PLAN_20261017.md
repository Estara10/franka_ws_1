# 无 weld 接触抓取：两次有界实验计划

日期：2026-10-17。状态：**计划，尚未执行**。

依据：[问题简报](CONTACT_GRASP_ANALYSIS_BRIEF_20261017.md)、[分析结果](CONTACT_GRASP_ANALYSIS_RESULT_20261017.md)、[项目指南](PROJECT_GUIDE.md)。

## 1. 目标与范围

判断“摩擦软约束及 pyramidal 法向/切向耦合”是否是当前承载失败的主要原因，并尝试获得一次完整的真实接触抓放。

固定场景 `(x,y,yaw)=(0.50 m,0 m,+10°)`，完成：

```text
预抓取 → 下降 → 闭合 → 抬升5 cm → 保持2 s → 落回支撑面 → 松开
```

本轮最多启动两次新的任务仿真，不自动重试，不开展参数扫描。只研究接触承载，不加入横向运输、旋转、柔顺或视觉。一次通过代表该固定场景功能通过，不代表成功率或泛化能力。

## 2. 执行前必须处理的实际差异

编写本计划时读取到：

| 项目 | 简报基线 | 当前工作树 | 处理方式 |
|---|---|---|---|
| 指令抬升高度 | 0.05 m | `contact_load_probe.cpp` 中 `height=0.06` | 为本实验准备独立的5 cm配置/快照 |
| 运动阶段滑移阈值 | 0.005 m | `lift_slip_tol=0.012` | 本实验运行时应按5 mm停止，不能只事后筛掉超限样本 |
| 轨迹时间 | 历史约31.91 s | 当前速度/加速度比例0.50/0.30，需核对实际轨迹 | 两组保持同一轨迹生成与时间参数化；记录实际时长 |
| 模型加载 | 文档常引用源码 | launch实际从安装目录加载；本机安装XML是普通文件 | 核对安装副本与本轮实验配置一致 |
| 驱动及闭合窗口 | 130603历史设置 | 相关代码已有修改 | 核对实际驱动模式、gain/bias、力限及闭合判据，不能只看注释 |

当前修改可能属于用户的其它实验，本计划**不授权回滚这些修改**。执行时保留现有工作树，通过独立副本/实验配置建立本计划基线；不得用 `git reset`、`checkout --` 或覆盖安装目录旧文件来冒充恢复历史版本。

历史 `130603` 只有在驱动、接触过滤器、指垫、轨迹、判据及实际加载版本可确认一致时，才可作为单因素对照。否则采用第4节的“基线未确认”分支。无需全量哈希，保留相关配置、代码差异及运行日志即可。

## 3. 冻结条件和成功标准

两组共同条件：

| 类别 | 固定设置 |
|---|---|
| 软件与积分 | MuJoCo 3.2.0；timestep=0.002；implicitfast；Newton；iterations=50；tolerance=1e-9 |
| 杆 | 原尺寸、质量约0.64 kg；重力不变；摩擦3.0/0.5/0.005；solref=0.005/1 |
| 指垫 | 每指一个主pad；size=0.010/0.006/0.010；solref=0.02/1；原solimp；禁用辅助pad及mesh–rod接触 |
| 夹爪 | armature=0.1；kp=1200；原0.5/0.5腱；请求10 N/指；运行时腱力限±20 N；同一保持实现 |
| 其它求解设置 | condim=6；noslip_iterations=0；不增加显式pair或solreffriction |
| 手臂 | rigid；内部柔顺关闭；只允许dual_panda_arm_controller active，sim_multi_mode_controller不得同时active |
| 轨迹 | 同一初始场景、抓取偏置、IK和时间参数化；指令上升0.05 m；不主动改变运动速度 |
| 物体状态 | 初始设置一次已知位姿；任务开始后不写杆位姿，不加托举外力，不启用手–杆固定约束 |

成功必须同时满足：

1. 闭合通过冻结的原接触窗口，且任务规划与执行均通过现有检查。
2. 保持期间杆相对初始高度至少上升45 mm，持续至少2 s物理时间；保留现有不少于20个新双侧反馈样本要求。
3. 从抓取参考建立后，任一手相对杆漂移不超过5 mm/2°，不能在LIFT/HOLD之间重新置零掩盖滑移。
4. 保持窗口内每指有效受力样本占比至少80%，有效力阈值沿用原实现；闭合窗口另外记录。
5. 全程两侧weld与所有固定杆的约束均未启用；手指间同步joint equality保留。
6. 完成落回、松开，保持驱动清除；同时有 `CONTACT_LOAD_VALIDATED`、`CONTACT_PROBE_RELEASED` 和 `CONTACT_PROBE_RESULT state=DONE`。

承载时只允许预期手指–杆接触；放置前后杆–支撑面接触正常保留，其余碰撞检查不豁免。单个成功日志、接触帧存在、瞬间合力达到杆重均不能代替上述条件。

## 4. 两次仿真的分配

### 分支A：历史基线已确认可比

| 运行 | 相对对照唯一改变 | 要检验的假设 | 预期观察 |
|---|---|---|---|
| E1 | 相对130603仅 `cone: pyramidal → elliptic`；impratio仍为1 | 改变摩擦锥表示能否改善接触稳定性/承载响应 | 闭合保持稳定；比较向上力、滑移速度、接触占比及轴向漂移。可能改善，也可能单换锥不足 |
| E2 | 相对E1仅 `impratio: 1 → 10`；保持elliptic | 解耦后提高摩擦阻抗能否在原滑移限制内承载 | 地面卸载时指垫向上合力接近杆重；杆跟随手上升，并在保持阶段持续承载 |

E2有条件执行：E1闭合稳定，且失败主要仍是低摩擦利用率的竖直滑移。E1已完整成功则不执行E2；E1闭合失稳、碰撞/控制失败、或轴向漂移主导时，也不执行E2。不凭“没成功”就继续加阻抗。

### 分支B：历史基线无法确认可比（当前工作树优先采用此分支）

| 运行 | 配置 | 用途 |
|---|---|---|
| B0 | 冻结后的5 cm/5 mm配置；pyramidal、impratio=1 | 建立当前实现的对照，确认是否仍为闭合稳定而竖直承载失败 |
| E1 | B0的同一构建、同一参数，仅改为elliptic | 形成有效的单因素比较 |

若B0已成功，本轮结束；若B0未进入有效抓持/抬升或失败机制明显不同，先分析，不盲跑E1。该分支已用满两次仿真，**本轮不再运行E2**。历史数据仍可解释背景，但不作为严格单因素因果证据。

## 5. 配置与启动方法

执行人可以是本机AI或用户，无需逐次另行申请仿真许可。每次运行前说明运行ID、唯一改变、命令与输出目录。只启动一个仿真，运行之间确认上一轮自有进程已退出。

实际调用链：

```text
scripts/run_contact_probe_local.sh
  → scripts/a1_run_scene.sh --grasp-model contact_probe
  → sim_dual_moveit.launch.py（已包含MuJoCo）
  → 安装目录 franka_description/mujoco/franka/dual_scene.xml
  → mj_dual.xml + objects.xml
```

模型参数来源是 `src/multipanda_ros2/franka_description/mujoco/franka/mj_dual.xml` 的 `<option>`；主pad参数还会被硬件插件的 `CONTACT_PROBE_SINGLE_PAD` 分支覆盖，必须核对运行时记录，不能只看XML。

下面是**完成第2节独立基线准备、并使对应安装环境生效之后**的启动模板。当前工作树直接执行会跑6 cm/12 mm版本，不能作为本计划结果。

```bash
# 从准备好的实验工作区根目录执行；ID按B0/E1/E2选择，不能复用目录。
rtk proxy env \
  CONTACT_PROBE_RUN_ID=contact_cone_E1_20261017_01 \
  CONTACT_PROBE_DOMAIN_ID=113 \
  CONTACT_PROBE_RIGID=true \
  CONTACT_PROBE_HOLD_DIAGNOSTIC_ONLY=0 \
  bash scripts/run_contact_probe_local.sh
```

该入口默认使用本机已有MuJoCo目录，启动可视化任务，不自动构建。它将生成：

```text
experiment_results/a1_runs/<RUN_ID>/
launch_logs/<RUN_ID>/
```

如果实验配置需要构建，只构建受影响的包；XML更新需同步正确的franka_description安装副本，任务阈值或轨迹实现变化需重建dual_arm_carry_task，驱动实现变化才涉及franka_hardware。在独立实验工作区中使用其自己的build/install/log，构建后再次确认入口加载路径。此准备过程不顺带升级依赖或修改生产默认值。

每轮启动后核对：MuJoCo版本、cone/impratio/timestep、任务CONFIG中的高度/滑移阈值、驱动实际gain/bias和力限、控制器状态。现有日志若未输出cone/impratio，增加只读启动日志；不可仅凭环境变量名称判断参数已生效。

## 6. 最小记录与比较方法

保留完整失败目录。每轮增加一个简短 `experiment_notes.md`，记录：运行命令、对照ID、唯一改变、实际加载模型路径、相关配置差异、轨迹时长和失败原因。

主要文件：

- `task_launch.log`、`sim_dual_moveit.log`、`prepare_status.json`、`controllers.txt`；
- `contact_probe.csv`：阶段、杆位姿、双手位姿、滑移、四指受力、约束状态；
- `contact_probe_contacts.csv`：逐接触几何、六维力、实际驱动与接触参数；
- `gripper_fingers_mj_left.csv`、`gripper_fingers_mj_right.csv`。

两组均报告以下指标，不只挑选有利片段：

| 指标 | 计算口径 |
|---|---|
| 闭合与保持接触占比 | 分窗口、分四指统计有效受力样本/有效反馈样本；不把接触点行数作为分母 |
| 杆最大升高、保持最低升高 | 相对同一初始真值；保持指标使用完整HOLD窗口 |
| 最大滑移与角漂移 | 左右分别统计，取较差侧；同时报告首次超限物理时间 |
| 向上接触合力 | 两臂对杆的世界系Fz相加；注明反馈是否同步 |
| 竖直与轴向相对运动 | 用实际手/杆位姿计算；轴向按杆方向投影，不用世界y直接代替 |
| 摩擦利用率 | 平移利用率与六维锥占用分开解释；不同锥不直接比较efc行力 |
| 任务结果 | 未启动/闭合失败/LIFT失败/HOLD失败/释放失败/完整通过，保留原错误码 |

建议输出一张三联时序图：杆与双手升高；左右滑移及5 mm线；向上合力及6.28 N参考线。使用物理时间并标记阶段，不能把失接触样本从图中删除。若有求导，用明确的短窗差分，报告窗口；不将力—位移斜率直接命名为切向刚度。

只有发生新的难以解释的失稳时，再在短时间窗增加每2 ms记录的接触距离、法/切向速度、地面竖直力和约束R/vel/aref/force。首轮不先扩建诊断系统。

## 7. 停止、解释与交付

单次停止条件：沿用冻结后的5 mm/2°阈值、闭合失败、碰撞、反馈停滞/非有限值、控制器错误、约束污染或现有超时。悬空失败按现有失败路径停止手臂，不自动开爪；runner只结束本轮自有进程，禁止大范围清理。

观察结果按下表解释：

| 观察 | 允许得出的结论 | 不允许得出的结论 |
|---|---|---|
| E1完整通过 | 该场景下只换锥已足够解决本轮失败 | 普遍稳定、成功率已验证、数值误差已消除 |
| E1更稳但仍竖直滑移 | 单换锥不足，可按预算考虑E2 | 必须加摩擦或放宽滑移阈值 |
| E2通过 | elliptic下该阻抗配置可完成本场景 | pyramidal失败已被唯一归因 |
| 强化后轴向漂移/失接触 | 存在另一耦合或跟踪瓶颈，停止继续增强 | 杆质量过大、摩擦容量不足 |
| 两轮均失败 | 候选修复未验证成功，记录失败阶段和差异 | 所有真实接触方案不可行 |

到达一次完整通过，或两次预算用完，或条件分支要求停止时，本轮结束。步长减半、armature、指垫几何及局部solreffriction不追加为本轮第三次实验。

交付仅需：两轮以内原始运行目录、一张比较图、一页结果表与下一步判断。不得将当前6 cm/12 mm版本的成功混入本计划5 cm/5 mm结论。
