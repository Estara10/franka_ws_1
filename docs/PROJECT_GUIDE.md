## 项目定位与长期开发准则

本项目属于**大学生创新创业训练项目**，以学习、研究探索、算法实现、功能验证和成果展示
为主要目标，并非商业交付、工业生产或长期无人值守的工程产品。技术标准与项目规模、
研究目标及具体风险相匹配，不照搬工业级治理、安全认证或生产级可靠性要求。

工作优先级为：**核心功能实现 > 实验效果与可靠性 > 开发效率与可维护性 > 必要安全保障 > 非必要的工程化完善。**
这不允许忽略已知严重风险；涉及人身、真实设备损坏或明显控制
失效的保护是底线，安全投入以实际风险为依据。

### 开发与验证原则

- **结果导向：** 优先处理影响当前功能、算法正确性、实验结果的实际问题。日志、文档、
  可追溯性服务于研究，不先于核心实现，也不以持续寻找规范缺陷代替开发。
- **简单实现与合理迭代：** 先完成清晰的最小可用版本，再依据测试改进。优先复用已有
  接口，避免无必要的抽象、架构、冗余检查和异常分支；不追求首次实现即生产级可靠。
- **适度验证：** 核心算法、接口和关键功能有必要测试。文档用链接/格式检查，简单参数
  用配置检查或一次相关冒烟，算法用针对性单测和小规模实验，运动/控制集成用相关仿真
  回归。纯仿真、离线及可重跑任务采用轻量方式，不要求每项修改跑完整系统或形式化验证。
- **按风险审阅：** 不强制所有代码或每个子阶段多轮独立审查。真实硬件风险、控制器
  资源冲突、并发写仿真状态等高风险变更，以及用户明确指定的审阅任务，做一次有重点的
  独立检查；仅在新变更、失败或未解决的关键疑问出现时复审。保留用户约定的规划器/执行器
  分工，常规提交可合并审阅，不新增多层审批。
- **基本记录即可：** 保留启动命令、关键参数、seed/位姿、算法/控制方式、运行结果和
  用于分析的原始数据。可用配置文件、简短日志和现有 Git 版本说明复现条件；不强制所有
  代码、模型、配置、结果做 SHA-256 或其他全量哈希。确实需要辨别模型/文件版本时，选
  简单差异比较、版本标记或必要校验即可，不建立复杂审计链、证据链或全面溯源系统。
- **成本与结束标准：** 开始任务时简要明确范围和少量验收条件，避免反复编写大篇文档、
  重复检查和冗余安全论证。结果达到约定且无阻断项即可完成；新发现的非关键问题记入
  后续事项，不追加为本轮必过条件。没有新变更或新疑问时，不重复已通过的检查。

### 问题分级与推进标准

| 等级 | 判断依据 | 处理方式 |
|---|---|---|
| 必须立即修复（阻断项） | 有依据的严重安全风险；当前核心功能无法运行；算法/数据明显错误；已发生或已复现的控制冲突、并发破坏、失败误报成功或不可恢复崩溃 | 修复影响本任务的部分并做针对性验证；说明实际影响，不扩展成全面治理 |
| 允许后续改进 | 不影响当前功能或结论的边界健壮性、关闭期警告、文档/格式问题、日志完善、可绕开的旧缺陷 | 简短记录局限，允许继续实现、调试和受控实验；严重程度随实际影响调整 |
| 当前不需要解决 | 无实际依据的极低概率假设风险、工业认证、全天候运行保障、复杂审计/全量哈希、与本轮无关的工程治理 | 不加入任务，不阻断交付，不为其新增基础设施 |

分级取决于实际影响，不取决于“安全”“审计”等标签。既有复杂机制也按实际收益评估：
必要的保留，冗余的简化，不合理的取消；本准则不授权无关代码重构或删除真实硬件保护。
已有失败和未完成项必须如实说明，但不要求消灭全部历史问题才开始下一步研究。

### 必要安全与质量底线

保留真实硬件涉及的急停、合理运动/力矩限幅与明显异常检测；当前不开展真机测试，不新增
真机安全认证工作。仿真保留基本关节/碰撞约束、控制器资源互斥、避免重复仿真实例、
避免无保护的并发状态写入，以及常见崩溃、控制失效、非有限数据和超时的基本处理。
不得把 ERROR 伪报 DONE、隐瞒失败、篡改实验结果或以代理指标冒充直接测量。
有证据表明会丢失用户数据、误清理他人进程或造成真实设备风险的问题应先处理。

## 项目目标和当前范围

项目基于 ROS 2 Humble、MoveIt 2、MuJoCo 和 ros2_control，研究两台 Franka Panda
协同夹持并搬运一根 40 cm × 4 cm × 4 cm 铝杆的轨迹规划与柔顺控制。

本次结题范围已调整为**仅开展仿真研究与验证，不进行实际机器测试**。系统集成、轨迹
优化、柔顺控制、扰动实验和性能评估均在 MuJoCo 中完成；真机部署、实机演示及仿真与
实机结果对比不属于本次结题要求。结题目标修订文本、实验设计和指标口径见
[`deliverables/结题目标修订说明.md`](deliverables/结题目标修订说明.md)。

当前唯一开发主线位于 `src/multipanda_ros2`。根 `src/dual_arm_*` 四个早期包已移至
`archive/legacy_dual_arm_stack`，不再参与 colcon 枚举或运行。

根据用户最新安排，后续工作从 A1 开始，按功能依赖逐步推进：

1. A1 接口与配置核查，保留 A0 为全过程回归基线。
2. A1 可复现场景与独立真值输入。
3. A1 样本有效性检查，以及阻碍该链路的模式 A 安全与可靠性修复。
4. A1 全流程泛化：物体空间轨迹、协调 IK、完整碰撞检查和统一时间参数化。
5. 真实轨迹优化与内部柔顺基线评估。
6. 在仿真中完成外部笛卡尔阻抗链路，并与内部柔顺对比后决定默认方案。
7. 冻结模型与实验配置，开展正式 A0/A1 对比与扰动实验，整理结题成果。
8. 基础场景、位姿输入、必要检查和搬运可运行后，尝试 B 视觉；可与后续核心研究穿插，
   不必等待所有非关键事项收尾。先做静态位姿估计，再接入搬运并与 A1 真值输入对比。

执行器分阶段任务、交付物和审阅标准见
[`deliverables/从A1开始的阶段计划与执行器提示词.md`](deliverables/从A1开始的阶段计划与执行器提示词.md)。
提前开展 A1 保留相关规划、碰撞与控制验证；基础任务可运行并通过必要检查后可做受控实验，
不以全部非关键健壮性或记录机制完善作为前提。

视觉目前只是实验性框架，不是现阶段验收主线；用户已明确希望在基础工作完成后尝试接入，
详细门槛见阶段计划的 P7。

## 当前活动架构

### 启动和仿真层

- `start_dual_arm_task.sh`：当前一键入口，负责模式选择、环境加载、必要构建检查、启动和日志。
- `franka_moveit_config/launch/sim_dual_moveit.launch.py`：启动 MoveIt，并自动包含 MuJoCo；
  不得再并行单独启动第二个 MuJoCo 实例。
- `franka_hardware/src/sim/franka_mj_hardware_system.cpp`：MuJoCo 与 ros2_control 的硬件接口，
  同时实现当前内部柔顺和抓取 weld 约束。

### 任务层

`src/multipanda_ros2/dual_arm_carry_task` 是当前任务包：

- `carry_task_state_machine.cpp`：节点、参数和同步 FSM 循环。
- `dual_arm_controller.cpp`：MoveIt 接口、IK、轨迹、PlanningScene 和抓放逻辑。
- `gripper_controller.cpp`：左右夹爪 action 客户端。
- `adaptive_compliance_supervisor.cpp`：外部阻抗参数监督器，默认关闭。
- `communication_latency_monitor.cpp`、`task_metrics_monitor.cpp`：实验指标节点，均为 C++。

状态顺序为：

```text
INIT → APPROACH → GRASP → WAITING_PHYSICS → LIFT → TRANSPORT
     → ROTATE → DESCEND → PLACE → RETREAT → DONE
```

任一动作失败应进入 `ERROR`，不得以 `DONE` 掩盖失败。

### 抓取与对象状态

夹爪闭合后，任务发布 `/grasp_weld_active=true`，MuJoCo 硬件插件启用左右手与杆之间的
weld；同时任务把杆作为 AttachedCollisionObject 加入 MoveIt。放置时逆序解除 weld、
打开夹爪、detach 并把杆恢复到世界场景。仿真场景和 PlanningScene 必须保持一致。

## 轨迹规划的真实状态

当前接近和部分抓取动作使用 Pilz PTP；运输、旋转和下降主要由逐点 IK 手工构造轨迹，
随后使用 TOTG，部分路径再使用 Ruckig。MoveIt 配置虽然注册了 CHOMP，但核心任务代码
目前没有真正调用 CHOMP。因此 `chomp_only` 和 `compliant_chomp` 仍是历史模式名，不能
把它们描述成已经完成 CHOMP 优化的实验组。

后续目标链路是：

```text
物体空间杆轨迹
  → 左右固定抓取变换
  → 协调 IK
  → 关节限制、环境碰撞、自碰撞与双臂相对约束检查
  → 真实轨迹优化
  → Ruckig 统一时间参数化
  → 位置控制或阻抗控制执行
```

## 柔顺控制的真实状态

### 内部柔顺

内部柔顺位于 MuJoCo 硬件插件的位置伺服环。它根据双腕受力估计降低关节位置增益、提高
阻尼，同时继续跟踪 `dual_panda_arm_controller` 的关节位置轨迹。准确称呼是“基于内力的
自适应关节伺服增益”，不是完整笛卡尔阻抗或导纳控制。它目前可用于仿真基线。

### 外部柔顺

`adaptive_compliance_supervisor` 只根据力反馈调节笛卡尔刚度和阻尼；它本身不生成连续的
期望末端轨迹。完整外部阻抗还需要轨迹到末端目标的桥接、无跳变控制器切换、力矩限制、
超时保护和恢复策略。

`dual_panda_arm_controller` 与 `sim_multi_mode_controller` 不能同时 active。外部监督器默认
关闭是为了避免控制资源冲突，而不是已经完成集成。外部阻抗应先在 MuJoCo 中验证：若成功率、
精度和内力/振动指标均可靠，再作为正式方案；否则保留为 experimental，仿真默认继续使用
内部柔顺。

长期实验模式计划为：

| 模式 | 轨迹优化 | 柔顺控制 |
|---|---|---|
| `baseline` | 无 | 无 |
| `optimized` | 有 | 无 |
| `compliant` | 无或同一基础轨迹 | 笛卡尔阻抗；完成前由内部柔顺作基线 |
| `optimized_compliant` | 有 | 笛卡尔阻抗 |

当前命令行仍使用旧模式名，重命名属于后续功能阶段。

## A0、A1 和 B

- A0：固定初始位姿，用于快速回归构建、状态机、规划和控制。
- A1：MuJoCo 按固定 seed 采样已知杆位姿；任务使用真值。样本必须通过桌面边界、双臂 IK、
  组合碰撞和预抓取路径检查后才接受。
- B：任务只使用视觉估计位姿，并用仿真真值评价位置和角度误差。

当前 `scripts/vision_core.py` 和 `/detected_rod_pose` 只构成框架。它尚无可信的完整成功记录，也没有
完成 CameraInfo/TF 标定、角度消歧、稳定窗口和位姿冻结。

## 已确认的验收方向

- 模式 A 先于模式 B。
- 仅仿真验收，不开展真机测试。现有通用控制接口可以保留，未来真机迁移只作为展望，
  不新增本次结题所需的硬件适配或测试任务。
- 末端误差 2 mm 是优化目标；阶段性功能门槛可以为 3 mm，但必须如实报告。
- 铝杆目标质量为 0.5 kg。当前 MuJoCo 模型按尺寸和密度计算约为 0.64 kg，本阶段不修改。
  正式实验说明实际质量；如后续修正模型，做相关回归，不混用两种模型的数据。
- 实验原始数据保留；单次自动报告未来按正式结果与原始运行分层管理。
- 完成可复现的仿真对比实验，区分功能完成、性能达标与实验性功能；历史模式名和代理
  指标不能作为真实轨迹优化、完整笛卡尔阻抗或物体放置精度已完成的证据。

## 必须跟踪的技术风险

1. 手工逐点 IK 轨迹没有完整的碰撞有效性保证。
2. 夹爪 action 回调捕获栈变量，存在超时后的生命周期和数据竞争风险。
3. MultiThreadedExecutor 与同步 FSM 共享状态缺少明确同步。
4. SRDF/ACM 大范围禁碰及重复规则可能隐藏真实碰撞。
5. 当前一键脚本在模式 B 中会修改源码，并会复制生成配置回源码树。
6. 一键脚本使用较宽泛的进程清理，可能影响同用户其他 ROS 会话。
7. MuJoCo、PlanningScene、attach/detach 和 ACM 的对象状态有不一致日志。
8. jerk limit 不完整，旋转段没有统一经过 Ruckig。
9. 相机、`world` 与 `base_link` TF 链及标定尚不完整。
10. 同步误差、能量、末端误差和通信延迟目前包含代理量或异常样本，不能过度解释。

这是技术风险清单，不是全部必须先关闭的验收清单。部分条目来自早期观察，处理前核对当前
实现与实际影响，按上述三级标准决定立即修复、后续改进或本阶段不处理；不因此无限延期。
